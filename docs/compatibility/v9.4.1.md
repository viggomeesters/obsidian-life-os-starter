# Compatibility Report — v9.4.1

## Summary

`v9.4.1` keeps the 11-type vault contract and makes the public mirror more machine-consumable.

## Compatibility level

- **Note model:** compatible with the current vault contract.
- **Canonical intake:** direct-to-canonical locations remain the default; `00_inbox/` stays legacy/quarantine only.
- **Provenance:** automated captures should preserve `source`, `source_id`, `thread_id`, `topics`, and `project_slug` where known.
- **Public repo tooling:** adds generated JSON Schema, synthetic examples, checksums, and release bundle artifacts without changing note semantics.

## Migration guidance

1. Read `life-os-schema.yaml` as the source of truth.
2. Use `docs/generated-schema-reference.md` for quick human review.
3. Use `dist/vault-schema.schema.json` for editor/agent validation where JSON Schema is useful.
4. Use `examples/` as public-safe fixtures only; do not infer private vault contents from them.

## Known limits

The JSON Schema export validates common frontmatter shape and shared fields. Full semantic validation still lives in `scripts/validate_repository.py` and `scripts/validate_examples.py`.
